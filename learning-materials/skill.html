三、我的解释（个人化）

我把 Skill 理解成给 AI 的"岗位培训手册 + 工具箱"。裸模型像新来的聪明实习生：什么都能学，但不了解你的工作习惯；你每次都要从头教（重复写提示词）。Skill 就是把你教过一遍的东西固化下来：一套说明书（SKILL.md）、可能还有配套脚本和资料，打包成一个文件夹。下次遇到同类任务，AI 翻出这本手册就能直接上岗。

它有两个聪明的设计：一是按需加载——手册平时锁在柜子里（只留一张封面简介），真正接到相关任务才翻开，不占用宝贵的上下文桌面；二是沉淀复用——解决问题的经验从"聊天记录"变成"可版本管理的文件"，能提交到 Git、能分享给别人、能越改越好。Anthropic 的比喻很贴切：Skill 就像"让你打包专业知识的定制入职培训材料"。

四、核心机制 / 组成

一个 Skill 就是一个文件夹，核心是 SKILL.md（元数据 + 指令），旁边可放脚本和资源文件。Anthropic 总结的四大特性：

特性含义
可组合多个 Skill 可同时挂载，AI 自动识别并协调使用
可移植同一格式在应用端、CLI 工具、API 通用，一次构建处处可用
高效按需加载：只在任务相关时读取，只加载所需的最小内容
强大可以携带可执行脚本，适合"写代码比生成文字更可靠"的任务

存放层级（以 WorkBuddy / Claude 生态为例）：

层级路径作用范围
用户级~/.workbuddy/skills/个人所有项目可用（跨工作区）
项目级仓库根/.workbuddy/skills/仅本项目可用，随仓库共享给团队

本仓库的实例结构：

green-apple2026/
└── .workbuddy/
    └── skills/
        └── concept-tutor/      ← 项目级 Skill
            └── SKILL.md        ← 元数据 + 指令

五、具体应用场景

场景 1（本仓库）：我发现"把概念学明白"这件事会反复发生——课程每周都有新概念。与其每次重新描述"我要什么格式、要哪些小节、来源要核查"，不如把这些要求固化成项目级 Skill concept-tutor。本次作业的三份 HTML（agent / llm-context / skill）就是按它的流程生成的，下次学习"RAG"时只需一句"用 concept-tutor 学习 RAG"。这就是把一次性提示词升级为可复用资产。

场景 2（官方示例）：Anthropic 的技能市场里有处理 Excel（含公式）、PowerPoint、Word、PDF 的官方 Skill——这类任务"写脚本比让模型逐 token 生成文件更可靠"，正是 Skill"可以包含可执行代码"特性的用武之地。WorkBuddy 文档的实践案例也建议：先定义单一能力、把触发条件说清楚、从最高频的重复动作开始沉淀。

六、容易混淆的问题与使用边界

❌ Skill ≠ 一段提示词

一次性提示词用完即弃、存在聊天记录里；Skill 是文件、有元数据、可版本管理、可分享，触发和输出结构都被规范定义。

❌ Skill ≠ 工具（Tool）

工具是 Agent 的一次性"手"（如读文件、搜索），由模型逐次调用；Skill 是"方法论手册"，教 Agent 怎么组合动作完成一类任务。Skill 里可以指挥工具的使用。

  • Skill ≠ 插件/扩展的安装包：它本质是模型可读的指令与资源文件夹，不改变模型本身，模型能力仍由底层 LLM 决定。
  • 使用边界 1：值得沉淀才做 Skill。只做一次的任务写提示词即可；高频、流程稳定的任务才值得固化（WorkBuddy 文档："越高频的重复操作，越值得沉淀成 Skill"）。
  • 使用边界 2：安全责任。Skill 可能携带可执行代码，Anthropic 明确提醒"坚持使用可信来源的技能"——本作业仓库里的 Skill 全部是自己编写的，未引入第三方可执行脚本。
