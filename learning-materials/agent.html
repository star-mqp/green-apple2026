三、我的解释（个人化）

我把 普通 AI 对话理解成"一问一答的顾问"：你问一句，它答一句，答完就结束，从不真正动手。

而 Agent更像一个被授权的实习生：你给它一个目标（比如"帮我把这次课程的三个概念整理成网页笔记"），它不问你要每一步怎么做，而是自己拆任务、自己挑工具、自己检查结果；做错一步会根据报错反馈调整，直到任务完成才向你汇报。它和"顾问"最大的区别是过程控制权在自己手里——Anthropic 官方的定义正是"LLM 动态地指挥自己的流程和工具使用，并对如何完成任务保持掌控"。

再打个比方：Workflow 像地铁（轨道铺好，每站固定），Agent 像出租车（司机根据路况实时决定走哪条路，目的地不变）。

四、核心机制 / 组成

组成部分作用类比实习生的话…
LLM（大脑）负责理解目标、拆解任务、做每一步决策思考和判断能力
工具（Tools）读写文件、执行代码、搜索网页等实际行动能力电脑、办公软件、电话
循环 + 反馈（Agent Loop）执行→观察结果（含报错）→修正→再执行，直到完成做完一步看看结果对不对，不对就改
上下文（工作记忆）承载任务目标、历史步骤与中间结果工作笔记本（详见 llm-context.html）

五、具体应用场景

场景：本仓库就是例子。在 WorkBuddy（一个 Agent 产品）里，我输入"帮我完成作业：创建 Skill、生成三份概念学习资料并推送到 GitHub"，它自己完成了克隆仓库、创建目录、逐个写入 HTML、执行 git 提交和推送这一长串步骤。期间如果某步失败（比如网络超时），它会观察到报错并重试。这正是"LLM 动态指挥自己的流程和工具使用"——如果换成传统程序，需要程序员预先写死每一步的分支逻辑。

另一个对比场景：我想"每天早上 8 点把天气写进笔记"——这种流程完全固定的任务用 Workflow/定时脚本更稳，不需要 Agent 的动态决策。

六、容易混淆的问题与使用边界

❌ Agent ≠ 聊天机器人

聊天机器人只输出文字建议，不执行动作；Agent 有工具，能实际改变环境（写文件、发请求、跑代码）。

❌ Agent ≠ Workflow

Workflow 的流程由开发者预先用代码编排，LLM 只是被调用的"零件"；Agent 的流程由 LLM 自己临场决定。二者是谱系关系，不是对立。

  • Agent ≠ 万能：自主性带来不确定性——同样的任务两次执行路径可能不同，出错方式也更难预测。Anthropic 的建议是"从最简单的方案开始，只在确实需要动态决策时才引入 Agent"。
  • 使用边界：任务目标模糊需要探索 → 适合 Agent；步骤完全确定、追求稳定可审计 → 用 Workflow；只是问知识 → 普通对话即可。
  • 成本边界：Agent 循环多轮调用，token 消耗和出错概率都随轮数上升，简单任务用 Agent 是"高射炮打蚊子"。
