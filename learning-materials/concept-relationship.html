一、一句话总览（我的理解）

Agent 是"人"，上下文是它的"工作记忆"，Skill 是它的"经验手册"。三者不是并列的三个功能，而是同一个系统的三个层次：上下文决定了 Agent 此刻能"看见"什么，因此决定了它决策的质量；Skill是把反复教会的做事方法沉淀成文件，在合适的时机注入上下文，让 Agent 不必每次从零学习。Agent 提供了让上下文与 Skill 发挥作用的执行舞台；没有 Agent 的循环与工具，上下文只是静态文本，Skill 只是一份没人读的说明书。

三、两两关系辨析

① 上下文 → Agent：上下文决定 Agent 的工作质量

Agent 的每一次决策都只依据当前上下文：任务目标、工具说明书、历史反馈都在里面。上下文里没有的，Agent 就"不知道"；上下文里噪声太多，注意力被摊薄，决策就变差（上下文腐烂）。因此长任务中的压缩、结构化笔记、子 Agent 等手段，本质都是在管理 Agent 的工作记忆。同一个模型，上下文组织得好坏，直接决定同一个 Agent 聪明还是糊涂。

② Skill → 上下文 / Agent：Skill 是上下文的"外挂知识库"

Skill 把"怎么做某类事"的方法论保存在上下文之外的文件里，只在任务匹配时把最小必要内容注入上下文。对 Agent 而言，Skill 解决的是"经验不丢"问题：对话结束上下文就清空了，但 Skill 是文件，跨会话存在、可版本管理、可分享。Agent 借此获得"越用越熟练"的错觉——实际上是经验被沉淀复用了。

③ Agent → Skill：Agent 是 Skill 的使用者和创造者

Skill 不会自己运行，需要 Agent（在循环中读它、照它执行、调用它指挥的工具）才能落地；反过来，Agent 也能参与编写 Skill——比如本仓库的 concept-tutor 就是我在 WorkBuddy（Agent）里描述需求后生成、再由我人工核查修改的。这是一个"自举"闭环：用 Agent 造工具，工具再增强 Agent。

五、我的总结判断（个人观点）

学完三个概念后，我的整体判断是：这三个词描述的是"知识在不同时间尺度上的三种形态"——上下文是此刻的知识（用完即弃），Skill 是沉淀下来的知识（跨会话复用），而 Agent 是让知识转化为行动的机制。课程作业本身就是一个完整例证：我靠 Agent 完成了从建仓到推送的全流程（行动），靠管理上下文让它每一步都看到正确信息（此刻），最后把学习方法固化为 Skill（沉淀）。以后遇到新概念，成本从"重新教一遍"降为"一句话调用"。
