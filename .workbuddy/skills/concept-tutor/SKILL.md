# 概念学习资料生成 Skill（concept-tutor）

## 适用场景

- 正在学习一个陌生的技术概念（如 Agent、上下文、RAG、微调等），需要一份系统、结构化的入门资料
- 希望把零散的 AI 回答整理成可复习、可检索、可分享的学习笔记
- 需要为课程作业或个人作品集积累标准化的学习材料
- 输出为单文件 HTML，可直接在浏览器打开，无需任何依赖

## 输入信息

调用本 Skill 时需要提供：

| 输入项 | 必填 | 说明 |
|---|---|---|
| 概念名称 | 是 | 要学习的概念，如"大模型的上下文" |
| 学习背景（可选） | 否 | 学习者的现有基础，用于调整解释深度 |
| 关联概念（可选） | 否 | 希望在"概念辨析"中对比的相邻概念 |

示例调用方式（在 WorkBuddy 对话中）：

> 请使用项目级 Skill `concept-tutor`，学习概念「Agent」。

## 生成步骤

1. **拆解概念**：先判断概念属于哪一类（系统架构类 / 机制原理类 / 工程实践类），据此调整解释框架。
2. **收集来源**：优先检索官方文档、权威工程博客、规范或论文，记录每个事实的出处链接；无法核实的内容明确标注"待核实"，禁止编造来源。
3. **生成草稿**：按下方"输出结构"逐节撰写，解释必须用"个人化语言"重述（比喻 + 白话），不允许整段照搬 AI 对话或原文。
4. **事实核查**：对每个关键论断回溯到来源链接，确认链接真实可访问、内容确实支撑该论断。
5. **人工核查提醒**：在文档末尾生成"人工核查记录"空白区，学习者阅读后填写修改意见，确认资料经本人核查。

## 输出结构

每份学习资料为一个独立的 HTML 文件，保存到仓库 `learning-materials/` 目录，文件名为概念英文名（如 `agent.html`）。文档必须包含以下小节，顺序固定：

1. **学习目标**：3~5 条，用"读完本资料我能……"句式
2. **核心问题**：3 个以内的关键问题，驱动阅读
3. **我的解释（个人化）**：用白话和比喻解释概念本质，明确标注这是"个人理解"
4. **核心机制 / 组成**：分点说明，可用表格或示意图（内联 SVG，不依赖外部 CDN）
5. **具体应用场景**：至少 1 个贴近课程或日常的真实场景，说明该概念在其中如何发挥作用
6. **容易混淆的问题与使用边界**：2~3 组"X ≠ Y"式辨析
7. **自测问题**：5 道左右（含 2 道开放思考题），不提供答案，供复习自检
8. **参考来源**：3~6 个真实、可核查的链接（官方文档优先），每条注明"该来源支撑了文中的哪些论断"
9. **人工核查记录**：留白区域，记录本人阅读后的修改

## 资料来源要求

- 只允许引用真实存在、公开可访问的来源：官方文档（如 Anthropic/OpenAI/GitHub 的文档站）、权威工程博客、课程标准或论文
- 每个关键论断至少有一个来源支撑；观点性内容需标注"个人观点"
- 禁止使用无法打开的链接、来源与内容对不上的链接、AI 虚构的文献
- 中文资料优先引官方中文文档，英文资料注明语言

## 自检要求

生成后必须逐项检查，全部通过才算完成：

- [ ] 九个小节齐全，顺序正确
- [ ] "我的解释"是个人化重述，非原文照搬
- [ ] 每条参考链接均实际访问过且内容相关
- [ ] 应用场景具体、可落地，不是空话
- [ ] HTML 可直接双击打开，无外部依赖，无乱码
- [ ] 文档末尾已留"人工核查记录"区
- [ ] 已提醒使用者：发布前本人必须通读并填写核查记录
